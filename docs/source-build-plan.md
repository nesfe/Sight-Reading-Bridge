## 1. Что строим и чем это принципиально отличается от Piano Marvel / Synthesia

Тренажёр чтения с листа для фортепиано (Electron, десктоп). Главная и обязательная фишка — **режим повёрнутого на 90° нотного стана**.

**Критично — не перепутать с падающими плашками (read this twice):**

- Повёрнутый режим = **настоящий большой нотный стан, повёрнутый на 90° по часовой**. Сохраняются: пять линий каждого ключа, пробелы, ключевая раскраска, нумерация линий, головки нот, добавочные линии. Это читаемая нотация, просто её ось высоты совпала с клавиатурой.
- Высота звука → **горизонтальная ось** (низкие слева, высокие справа), и каждая «дорожка высоты» выровнена ровно над соответствующей клавишей экранной клавиатуры. В этом весь смысл: линия стана физически продолжается в клавишу.
- Время → **вертикальная ось**: ноты появляются сверху и падают вниз к линии «сейчас» над клавиатурой.
- Поворот — это **исчезающие леса (ось A из методики)**, а не постоянный режим. Цель — чтобы ученик потом читал тот же материал на горизонтальном (традиционном) стане. Synthesia/Piano Marvel дают падающие плашки как самоцель и не учат нотации — мы делаем наоборот.

Если возникнет соблазн упростить рендер до «прямоугольники падают на клавиши» — это ошибка, ломающая весь проект.

## 4. Спецификация `notation-renderer` (сердце проекта)

### 4.1 Система координат

Две раскладки, выбираются по оси A вектора лесов:

- `A = 1` → **vertical** (повёрнут 90° CW): `x ← высота`, `y ← время` (падение вниз).
- `A = 0` → **horizontal** (традиционный): `x ← время`, `y ← высота` (скролл справа-налево).

Это буквально поворот: высота и время меняются осями местами.

### 4.2 Диатоническая «ступень стана» — единый источник истины

```ts
// music-core/staff-geometry.ts
type Letter = 'C'|'D'|'E'|'F'|'G'|'A'|'B';
const LETTER_INDEX: Record<Letter, number> = { C:0, D:1, E:2, F:3, G:4, A:5, B:6 };

// staffStep растёт с высотой. Опора: среднее до C4 = 0 (это «0» из методики).
export function staffStep(letter: Letter, octave: number): number {
  return (octave - 4) * 7 + LETTER_INDEX[letter];
}

// ИНВАРИАНТ (использовать в тестах): линия <=> staffStep чётный; пробел <=> нечётный.
// Линии скрипичного: E4=2 G4=4 B4=6 D5=8 F5=10. Басового: G2=-10 B2=-8 D3=-6 F3=-4 A3=-2.
// Среднее до C4 = 0 — добавочная линия (чётная), как и положено по нумерации «0».
export const isLine = (s: number) => s % 2 === 0;
```

### 4.3 Выравнивание стана и клавиатуры — обязательное

Белая клавиша имеет **тот же индекс**, что и `staffStep` (обе последовательности — C D E F G A B). Значит у стана и клавиатуры **одна функция координаты высоты**:

```ts
// Одна функция-источник истины и для клавиш, и для дорожек стана.
// x центра дорожки высоты (vertical) == x центра соответствующей белой клавиши.
export function pitchX(step: number, kb: KeyboardLayout): number {
  return kb.whiteKeyCenterX(step);
}
// y по времени (vertical): будущее выше; по мере роста tNow y растёт к nowLineY.
export function timeY(tNote: number, tNow: number, nowLineY: number, pxPerSec: number): number {
  return nowLineY - (tNote - tNow) * pxPerSec;
}
```

В horizontal-режиме оси меняются: `pitchY(step)` и `timeX(t)` симметрично. Клавиатура рисуется только в vertical-режиме (снизу, дорожки приходят точно в клавиши).

**Чёрные клавиши / знаки альтерации:** для MVP материал диатонический (C-dur, белые клавиши) — это совпадает с начальным материалом методики. Бемольную/диезную ноту рисуем на `staffStep` её натуральной + глиф знака, дорожка между белыми. Реализовать после MVP.

### 4.4 Что рисует рендер (как чистая функция `(scene, scaffold) → SVG`)

- Линии стана (5+5) как дорожки вдоль оси времени, на позициях высот-линий.
- Тонировка опорных зон и нумерация линий 1–5 в каждом ключе, 0 для среднего до, бас нумеруется сверху вниз (ось D).
- Раскраска ключей разными цветами (ось C).
- Головки нот в (высота, время); длительность = длина «хвоста» вдоль оси времени (ось G — упрощённый/полный ритм).
- Имя ноты на головке (ось B); образ-ассоциация (ось E).
- Подсветка нужной клавиши на экранной клавиатуре (ось F).
- Линия «сейчас» (now-line).
- **Шторка** для Стадии 6 (см. майлстоун M6): закрывает ноты на участке *перед* now-line, заставляя читать вперёд.

Каждая ось управляется значением `0..1` из вектора лесов. Рендер не содержит педагогической логики — только отрисовку по вектору.

## 5. Спецификации остальных пакетов

**`music-core`** — типы `Pitch`, `Note {pitch, onset, durationBeats, finger?, chunkId?}`, `staffStep`/`isLine`/геометрия, `midiNoteToPitch`/`pitchToMidi`, детектор чанков (помечает группы: шаг/скачок/трезвучие/гаммовый фрагмент/повтор). Чистый TS, без DOM.

**`midi-io`** — обёртка над `navigator.requestMIDIAccess`. Перечисление входов, события `noteon/noteoff` с временной меткой из Web Audio clock, простой реактивный поток `onNote(cb)`. Обработка отсутствия устройства и отказа в разрешении. Никакого UI.

**`scoring-engine`** — главная педагогическая логика:
- Тип `Scaffold = { A,B,C,D,E,F,G: number }` (0..1).
- На каждую попытку считает: `noteAccuracy`, `rhythmAccuracy`, `latencyMs` (узнавание), `noHintRatio`, прокси-`eyeHandSpan` (горизонт шторки на M6).
- Адаптивный сдвиг: превысил порог по оси → подсказка по ней слабеет; провалил → возвращается. Пороги и шаг — конфиг.
- Проверка `exitCriteria` урока.
Покрыть Vitestّ-ом полностью — это ядро ценности.

**`exercise-engine`** — генерирует (1) осмысленные пьесы и (2) **«этюды для глаз»**: намеренно немелодичные последовательности с контролем диапазона, доли шагов/скачков и плотности (методика, Часть 5). Детерминированный seed для воспроизводимости.

**`curriculum`** — JSON-уроки по схеме из приложения методики + Zod-валидатор + 5–10 готовых уроков для Стадий 1, 3, 4, 6.

## 7. Майлстоуны (повёрнутый стан строится ПЕРВЫМ)

### M0 — Каркас
Монорепо (pnpm), Electron через electron-vite с secure-конфигом, React-renderer открывает окно. `midi-io` логирует список MIDI-устройств в консоль.
**DoD:** `pnpm dev` открывает окно; при подключённой MIDI-клавиатуре в консоли видны её noteon/noteoff.

### M1 — Повёрнутый стан (ОБЯЗАТЕЛЬНАЯ ФИШКА, без MIDI)
`notation-renderer` рисует vertical-режим: большой стан, повёрнутый 90° CW, оба ключа в цвете, нумерация линий, среднее до = 0, now-line, экранная клавиатура снизу с **точным выравниванием дорожек высот в клавиши**. Захардкоженная последовательность нот падает сверху к now-line.
**DoD:** на экране падают ноты по настоящему стану; визуально проверяемо, что дорожка каждой высоты приходит ровно в свою белую клавишу; инвариант `isLine` покрыт тестом.

### M2 — Живой MIDI-ввод
`music-core` + `midi-io`: нажатие на клавиатуре подсвечивает клавишу и засчитывается против падающей ноты у now-line. Базовый `noteAccuracy`.
**DoD:** играешь по падающим нотам, верные/неверные различаются визуально, точность считается.

### M3 — Вектор лесов и все оси рендера
`Scaffold` в Zustand. Реализовать рендер-отклик на оси B,C,D,E,F и переключение A (vertical↔horizontal). Временные слайдеры в UI для ручной проверки каждой оси.
**DoD:** каждой осью со слайдера видно меняется картинка; A=0 даёт корректный традиционный горизонтальный стан того же материала.

### M4 — Адаптивное снятие лесов + хранение
`scoring-engine`: метрики, пороги, автодвижение вектора, `exitCriteria`. Персист попыток и прогресса в SQLite через IPC. Запись каждой попытки (методика, Часть 6).
**DoD:** подсказки сами слабеют при успехе и возвращаются при провале; прогресс переживает перезапуск; ядро покрыто Vitest.

### M5 — Контент
`curriculum` (схема + валидатор + уроки) и `exercise-engine` (пьесы + этюды для глаз). Загрузка урока по id, проигрывание, фиксация результата.
**DoD:** можно пройти урок Стадии 4 (монофония из руки в руку) и сгенерированный этюд для глаз.

### M6 — Опережающее чтение (Стадия 6, ядро «взрослого пути»)
Шторка в рендере: закрывает ноты на регулируемом участке *перед* now-line, заставляя читать вперёд. Горизонт настраивается; прокси-метрика eye-hand span.
**DoD:** при горизонте ≥ 1 ноты играешь, не видя ноту в момент удара; метрика горизонта пишется в прогресс.

### M7 — Полишинг
Ритм-скоринг по сетке, опц. подсказка sight-singing (пропеть перед игрой), графики прогресса, упаковка под Windows (`electron-builder`), сэмплы пианино.
**DoD:** ставится как .exe, прогресс виден на графике.

> **Порядок не случаен:** самая рискованная и определяющая фича (повёрнутый стан, M1) и «взрослый путь» (M6) — приоритетны. Уже после M2 у Mike есть рабочий прототип под собственную проблему.
